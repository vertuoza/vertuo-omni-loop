PRD 68 · before / after

/omni:invade

A repository the loop moves into gets explored first. Its knowledge base then points at the rules the repository already writes down, and drafts the ones only its code knows.

What invade does

  1. Explore

    Four read-only scouts: domains, written rules, what the code enforces, ADRs and words.

  2. Show one map

    Everything found, with a default for each. You answer once.

  3. Write

    Index entries point at existing pages. Drafts come from the code. Playbook forms get filled.

  4. Open one PR

    Docs only. A person reviews and merges.

The safety rule

Every register entry invade writes carries Proposed: invade <date>. A proposed entry never stops a slice. It becomes a law when a person deletes that line.

A repository that already writes its rules down

Today

docs/business-rules.md has 40 rules. The loop can't cite them: they have no ids. /omni:terraform fills the playbook and leaves the registers empty.

.omni-loop/knowledge/domains/
  (nothing)

laws.source: none

A slice that breaks a written rule never stops, because the loop never learned the rule.

After

One short index entry per rule. The page stays the full text.

## BR-QUOTE-1
A quote expires 30 days after it is sent.
Serves: P-QUOTE-1
Source: docs/business-rules.md#quote-expiry
Enforced by: tests/Quote/ExpiryTest.php
Stated: 2026-09-25
Proposed: invade 2026-09-25

Delete the last line and BR-QUOTE-1 becomes a law the loop stops on.

The map, the one question

Today

Terraform takes one pass looking for pages that answer the playbook forms. Nobody is asked where the ADRs belong, and the domains aren't studied.

After

Rules        docs/business-rules.md   → index (40)
             README.md#concepts       → context only
From code    12 constraints           → draft
ADRs         docs/adr (18)            → point  | repatriate?

1. Keep these domains?
2. Index docs/business-rules.md?  (default: yes)
3. ADRs: point or repatriate?     (default: point)
4. Draft from code?               (default: on)

Answer once. Anything left unanswered takes its default. Nothing is written before the answer.

The name

Today

/omni:terraform, branches.terraform, terraformed:, by: terraform, "not terraformed".

After

/omni:invade, branches.invade, invaded:, by: invade, "not installed". Old form spellings still parse, with a warning.

What stays the same

  • The register layout and the playbook forms (PRD 45).
  • Nothing is written outside .omni-loop/. Repatriated ADRs are copied and the originals are never deleted.
  • A section a person wrote (by: human) is never rewritten.
  • A confirmed law behaves exactly as today.
