PRD 2879: before and after

kit

Functional

Today
  • A mission's mandate says one thing: how many PRDs run at once.
  • Every PRD of a mission is built on a branch cut from main, and its pull request goes into main.
  • A person runs /omni:mission; nothing lets a person take a PRD out of a mission's work.
After
  • The mandate also carries the level the mission runs at: Reviews with you, Own branch or Works alone. /omni:mission takes it from the fleet and asks nothing.
  • At Own branch and above, a mission's PRD is built on a branch cut from the mission's branch.
  • A person can drop a PRD from a mission's branch, and overturn a decision the fleet took.
  • A new skill lets the fleet's committee approve a PRD or answer a question, at Works alone only.

galaxy

Functional

Today
  • A Virtual Fleet is a name, an icon and its heroes.
  • The Missions tab shows each mission, its progress and every PRD that waits on a person: approve, answer, merge.
  • A PRD is approved by a person on its page.
After
  • A Virtual Fleet also has a level, chosen once when it is made. Only a workspace owner raises it.
  • The Missions tab shows the level, the mission's branch and its pull request, and under Waiting on you only what the fleet sent back, with why.
  • It shows how many decisions the fleet took and how many a person overturned.
  • At Works alone, a PRD's page can read Approved by fleet, for that mission.

omni-app

Functional

Today
  • A PRD whose job ends ready waits for a person to merge it into main.
  • A PRD blocked by another waits until a person merged the blocker.
  • One knowledge pull request is opened per merged PRD.
After
  • At Own branch and above, a ready PRD joins the mission's branch by itself once its checks are green, the Reviewer passed it and no high question is open.
  • The PRDs it blocked start at once.
  • The mission's branch follows main, and one pull request carries it to main: a person merges it, and main gets one commit per PRD.
  • One knowledge pull request is opened per landing, for every PRD it landed.
  • At Works alone, the committee's three members vote; anything but three yes, and everything on the list no vote can settle, goes to a person.

database

Functional

Today
  • A fleet has no level.
  • A mission's mandate holds one number.
  • Nothing records a decision taken by a fleet.
After
  • A fleet has a level, Reviews with you unless an owner raised it.
  • A mission's mandate holds its level and two bounds.
  • Each decision of a committee is kept: who voted what, what was carried, what went to a person, what a person overturned.

  • A person starts a mission; it takes its level from its fleet.
  • The App cuts the mission's branch from main and sends each PRD's job, built on that branch.
  • A PRD's pull request goes into the mission's branch; the Reviewer reads it.
  • Green checks, the Reviewer's pass and no open high item: the App squash-merges it and rewrites the mission pull request.
  • At Works alone, committee jobs approve a PRD or answer a high item, or send it to a person.
  • A person merges the mission pull request with Rebase and merge; the App opens one knowledge pull request for the landing.

Deploy order

  • database: one additive migration (the fleet's level, the mandate's shape, the new event kinds, mission_decisions). It reaches production with the merge, before any code reads it.
  • kit: the brief's fields, branches.mission, the two commands and the committee skill; released by the version commit.
  • omni-app, then galaxy: each deploys from the release commit. Until a fleet's level is raised, neither does anything new.
  • A person, once: allow rebase merges on main.

Behaviour

Today
  • /omni:yolo, /omni:wave, /omni:pr and /omni:pr-care take main as a feature branch's base.
  • A hero never merges and never answers for a person.
After
  • They take the base their job names: the mission's branch for a mission at Own branch or above, main otherwise.
  • A hero still never merges into main. At Works alone the committee answers in the fleet's own name, never a person's.

Behaviour

Today
  • A ready PRD waits for a person's merge; a merged PRD unblocks the next.
  • The knowledge harvest runs for each feature pull request merged into main.
After
  • At Own branch and above, a ready PRD that passes the merge gate joins the mission's branch and unblocks the next.
  • The mission's branch is rebased when main moves; a conflict outside generated files changes nothing and waits on a person.
  • The harvest runs once for a merged mission pull request.
  • A mission at Reviews with you behaves exactly as before.
