Adopting Omni Loop: by hand today, omni init after

What a person does to put the loop on a repository (TypeScript, PHP or any other), before and after this PRD. The skills, the config schema and the omni-loop App stay as they are.

Today: by hand

  1. Write .omni-loop/config.yml from memory or by copying another repo's. Nothing checks it until a skill or the App reads it. A typo shows up as a red check.
  2. Copy the bundle to .omni-loop/bin/omni.mjs. Forget it and every skill stops at step 0: “not terraformed”.
  3. Create prd, pr:phase-0, pr:feature, pr:sub, pr:in-progress, pr:needs-fix, outbox:go one by one. This repository still has none of them.
  4. Find out from a README somewhere that the plugin and the omni-loop GitHub App are needed too.
$ gh label create prd
$ gh label create pr:phase-0
…five more…
$ node .omni-loop/bin/omni.mjs config
This repository is not terraformed: .omni-loop/config.yml is missing.

After: one command

$ node ../vertuo-omni-loop/.omni-loop/bin/omni.mjs init
omni init — vertuoza/vertuo-workflow-domain is set up.
  wrote   .omni-loop/config.yml
  wrote   .omni-loop/bin/omni.mjs
  labels  created prd, pr:phase-0, pr:feature, pr:sub,
          pr:in-progress, pr:needs-fix, outbox:go

Commit .omni-loop/ and merge it into main, then, by hand:
  1. Install the omni plugin in Claude Code:
       /plugin marketplace add vertuoza/vertuo-omni-loop
       /plugin install omni@omni-loop
  2. Install the omni-loop GitHub App on this repo:
       https://github.com/apps/omni-loop-invader/installations/new
  3. (Optional) Require the `outbox` check on main:
       https://github.com/vertuoza/vertuo-workflow-domain/settings/branches
     Warning: a required check that is never posted blocks
     every pull request in this repository. …

To remove the loop: delete .omni-loop/ and commit.

A second run keeps the config and the bin, creates no label, and exits 0. --force rewrites the files. Existing labels are never recoloured.
