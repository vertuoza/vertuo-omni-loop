PRD 2684: before and after

omni-app

Functional

TODAY

You push to a pull request. GitHub tells the Omni GitHub App, which hands the work to Inngest.

Inngest waits 5 seconds for more pushes, then runs the four checks: outbox, inbox, approved, budgets.

When the Inngest account has used its monthly allowance, it runs nothing. No check is published, and the pull request waits with no word of why.

AFTER

You push to a pull request. GitHub tells the Omni GitHub App, which writes the work in its own job ledger.

The App waits 5 seconds for more pushes, then runs the same four checks itself. Their names, results and words are the same.

No allowance can stop them. A check that fails for good is shown as failed, with the reason, and the App's health page says when checks run late.

The same holds for re-running a check, a change of the approved label, an approval given on a PRD's page, and the buttons on a red canon check.

Flow

Deploy order

  1. Merge: the migration applies through the supabase workflow. It only adds.
  2. The App deploys with the sweep every minute and its two routes at 300 seconds.
  3. Until both are live, a delivery may answer 500: redeliver it, or re-run the check.
  4. Nothing to change on Inngest: its seven functions are no longer served.

Behaviour

TODAY
  • A check is an Inngest function cut into saved steps.
  • 3 retries on Inngest's own waits.
  • On the last failure, an Inngest failure handler completes the check as a failure.
  • approvedRerun and serverEvent send one event per pull request.
AFTER
  • A check is a ledger job that re-runs whole.
  • 4 tries, waiting 10 seconds, 1 minute, 5 minutes; a low GitHub budget waits 15 minutes and gives the try back.
  • A job that becomes failed runs its kind's failure handler once.
  • approved-rerun and server-event add one debounced check job per pull request.
