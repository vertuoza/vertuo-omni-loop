PRD 72 · before / after

The retro

When a feature PR merges today, nothing looks back at how it was built. After this PRD, the omni-loop app counts what went wrong, opens a retro PR and one retro issue per finding, at the merge and again 14 days later.

Example data throughout: a PRD in a repository that runs CI, drawn to show the shape of the pages. Every number on a real retro is counted by code from GitHub and the PRD's folder.

What stays the same

Unchanged

The outbox checkA merge never becomes an outbox event, and the retro never reads or writes a check run. The retro PR gets the check skipped, like any PR that is not a feature PR.
Nothing in the repository runsAll of it runs in the app on Vercel. No workflow, nothing under .github/, no repository code executed.
A person mergesThe app opens branches and pull requests of its own and never writes to main.
PRDsA retro issue is never labelled omni:prd. Planning and delivery work as before.
Without a model keyThe retro still opens, with the same findings and issues, and says the prose is missing.
