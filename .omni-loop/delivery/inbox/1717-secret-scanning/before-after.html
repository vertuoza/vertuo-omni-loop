Secret scanning, switched on and kept on

PRD #1717 · Bounded, no product code. A public repository gets GitHub's secret scanning and push protection, fake secrets that never trip them, and a daily check that keeps them on.

Functional

1 · The repository's settings

Today

vertuoza/vertuo-omni-loop   public
security_and_analysis
  secret_scanning                  disabled
  secret_scanning_push_protection  disabled
  dependabot_security_updates      enabled
  • A real token pushed by mistake is public at once, and nothing raises it.
  • Nothing would notice a setting switched off.

After

vertuoza/vertuo-omni-loop   public
security_and_analysis
  secret_scanning                  enabled
  secret_scanning_push_protection  enabled
  dependabot_security_updates      enabled
  • A push holding a real credential is refused before it lands.
  • Switched on by node scripts/security-settings.ts --apply; the whole history scanned once, every alert triaged in the feature PR.

2 · A fake secret in a test

Today

// apps/galaxy/src/jev/mask.test.ts
const FAKES = [
  'ghp_abcd…6789',          // written out whole
  'sk-ant-api03-abcd…wxyz',
];
  • Once push protection is on, an agent adding one like it could be refused, and the briefing forbids bypassing.

After

// apps/galaxy/src/jev/mask.test.ts
const FAKES = [
  'ghp_' + 'a'.repeat(36),  // built at runtime
  'sk-ant-' + 'api03-' + 'x'.repeat(26),
];
  • The test receives a string of the same shape, so what it proves is unchanged.
  • scripts/secret-shapes-guard.test.ts refuses a literal one in any tracked file, naming the file, the line and the shape, in the agent's own run.

3 · When something goes wrong

Today

A setting switched off, or a secret pushed: no run, no issue, no one told.

After: the daily security workflow

$ node scripts/security-settings.ts
secret scanning     enabled
push protection     disabled  → node scripts/security-settings.ts --apply
open alert #3       github_personal_access_token
                    → https://github.com/vertuoza/vertuo-omni-loop/security/secret-scanning/3
exit 1
  • Red: opens one omni:security issue with this output, or comments on the open one.
  • Green again: closes that issue.
  • Reads with SECURITY_READ_TOKEN (Administration: read, Secret scanning alerts: read, this repository only); off until it is set.
