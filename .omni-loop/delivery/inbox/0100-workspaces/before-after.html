PRD #100 · before / after

Vertuoza becomes the first workspace

A workspace now owns every fleet, sector, player and ledger event, along with its GitHub organisation, its mark and its colours. Vertuoza is workspace #1 and looks and plays exactly as it does today. The database, the game scripts and the arcade are ready for a second company.

This is the first of four PRDs. Open sign-up (2), the setup page with the GitHub App (3), and editable fleets with solo play (4) come next. Nothing on this page changes what a Vertuoza player sees.

Who owns the data

From one global galaxy to one galaxy per workspace

Today the email domain decides everything. After, membership does, and each workspace sees only its own rows.

The ledger

Two companies, each with a PRD #12

Event ids carry no organisation. Today the second company's event would be dropped without an error. After, the key is the workspace plus the id, and nothing about the event itself changes.

The mark

The first letter of the workspace's name

The V becomes one letter of a bar alphabet drawn in its own style: split pill bars, the same caps, the same coral-to-blue gradient. Vertuoza keeps today's V pixel for pixel. The A and O below are sketches of the alphabet the build will draw.

The theme

Colours become tokens a workspace can override

Every colour on the arcade's :root, including the Game Boy's body from #94, plus the mark's gradient and the four stripes on the heroes' suits, becomes a named token. Each token defaults to today's value. A workspace stores only its overrides, and the database refuses an unknown token or a colour that isn't #rrggbb. The settings screen that edits a theme arrives with the setup page (PRD 3).

The game scripts

Every game script names its workspace

The projector reads the GitHub organisation and the plan repository from the workspace row. With no workspace named, a script stops instead of writing into the wrong one. The output lines below are illustrative.

What stays the same

Nothing a Vertuoza player sees changes

The same for players

  • The screens: "VERTUOZA PRESENTS", the V, "© 2026 VERTUOZA" and every colour, signed in or out, in demo mode and in the single-file artifact.
  • Sign-in: the Vertuoza Google account and the same copy. Open sign-up is PRD 2.
  • The joining flow: link GitHub, pick a fleet, enter a name, build a hero.

The same in the code

  • The game: the event contract, the event ids, the projector, the economy, the rulebook and @omni/galaxy.
  • Elsewhere: the GitHub App (apps/omni-app), the kit, and the personal token the game polls with.
  • The ledger is still append-only.

Changes once, on merge

  • Production's four game tables are rebuilt empty: production holds nothing worth keeping.
  • Everyone signs in again, joins Vertuoza automatically, and picks a fleet, name and hero once more.
  • Switch GAME_ENABLED off around the merge, and back on after the migration is applied.
