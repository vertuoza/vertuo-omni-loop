PRD 3215: before and after

galaxy-app

Functional

Today

Nobody can tell which settings page is slow or why; a page can get slower with no check noticing.

After

Each settings page has a measured profile and a written budget, and a test fails the day one gets slower. A preview shows where a request's time went.

Flow

N/A — one app, the galaxy app; no exchange between services.

Deploy order

One deploy of the galaxy app. No migration, no coordinated deploy; reverting the pull request is the rollback.

Database

N/A — no table, column or policy changes.

API / schema

The settings routes' responses gain one header, Server-Timing (added). Nothing else changes.

Behaviour

Today

Nobody can tell which settings page is slow or why; a page can get slower with no check noticing.

After

No page's behaviour changes. A settings response gains a Server-Timing header.
