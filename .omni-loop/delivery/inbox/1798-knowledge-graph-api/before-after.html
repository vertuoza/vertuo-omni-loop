PRD 1798 — before and after

PRD 1798 · P6 of the roadmap "Governed knowledge" · The knowledge graph API on the server · blocked by 1797 (P5)

Functional

Today a repository's graph lives only in its own terminal (P5). After, each repository pushes it, the server joins the product's repositories with its Legal and Glossary, and anyone in the workspace reads the whole.

Where the knowledge sits

Today

Nothing says which back-end rule serves which Legal entry, or that both repositories use the term "credit note".

After

One graph per product: API, CLI and a read-only tab. Each repository shows the commit it was pushed at.

Sending a repository's graph

Today

$ omni kb graph push
unknown command: kb graph push

The graph (P5) never leaves the checkout.

After

$ omni kb graph push
pushed vertuoza/vertuo-omni-loop@9086e70 · 412 nodes, 980 edges
in products: omni-loop · see https://www.omni-loop.xyz/app/products/<id>/knowledge

$ omni kb graph push   # knowledge edited, not committed
.omni-loop/knowledge has uncommitted changes: commit them, then push

Signed in like every other push (omni signin or OMNI_TOKEN). In this repository, a workflow also pushes after each merge to main.
