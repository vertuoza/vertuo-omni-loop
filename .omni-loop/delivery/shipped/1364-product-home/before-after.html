Products hold everything

Today a product is a name with Pitch and Approvers, and a repository belongs to exactly one product. After this PRD, products are optional and link to repositories many to many. Each product gets a home page with tabs, and a PRD carries its own product. Mobile, Estimates and the repositories below are examples.

3 · A PRD picks its product

When a PRD is born in a repository that is in one product, it takes that product. In a repository that is in none, it gets none. In a repository that is in several, the brainstorm asks once. The PRD's page can change the product until the PRD is approved.

4 · A plan repository names its product

plan.product replaces the hand-kept target list. omni targets prints the same table from the server, and keeps a local copy for when the server cannot be reached.

Today · .omni-loop/config.json
"plan": {
  "guide": "README.md",
  "targets": [
    { "repo": "vertuoza/vertuo-api",
      "role": "api", "knowledge": "own" },
    { "repo": "vertuoza/vertuo-mobile",
      "role": "mobile", "knowledge": "imported",
      "readAt": "3e9a1c0…", "consumes": ["api"] }
  ]
}
A second copy of what the product knows, edited by hand and drifting.
After · config, then the terminal
"plan": { "guide": "README.md", "product": "Mobile" }
$ omni product import --product Mobile

targets from the last read, 2026-10-09 · server unreachable
No product still works

A repository or PRD with no product builds as it does today: any member approves, and the workspace's region claims apply.

Existing links kept

Every repository keeps the product it has today, so every existing lookup gives the same answer.

plan.targets[] still accepted

A plan repository that keeps its targets list works unchanged. Setting both is refused.

Not in this PRD

The omni/approved check and the skills running from a product (product-gate), roadmaps, bugs and knowledge moving onto the server (product-records), and the Constellation tab.
