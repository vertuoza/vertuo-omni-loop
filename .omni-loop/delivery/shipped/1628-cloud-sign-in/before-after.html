Sign in from a cloud session

PRD 1628 · .omni-loop/delivery/shipped/1628-cloud-sign-in/ · today beside after. A Claude Code cloud session has no browser and starts empty every time, so the kit is never signed in there. After this PRD, a member pastes one personal token, OMNI_TOKEN, into their cloud environment once.

Functional

1. A command in a cloud session

Today 
$ omni whoami
signed out

$ omni dossier push 1628
omni dossier: no sign-in for www.omni-loop.xyz (omni signin)

$ omni signin
Sign in in your browser: https://www.omni-loop.xyz/ask/signin?port=…
… waits for a callback on 127.0.0.1, which no browser can reach

Ask mode, dossiers, approvals, the phase-0 flag, products and personas all stop here.

After 
# cloud environment variables, set once
OMNI_TOKEN=omk_••••••••••••••••••••••••••••••••••9fKa

$ omni whoami
ada (OMNI_TOKEN ··9fKa)

$ omni dossier push 1628
pushed spec.md v1 · before-after.html v1

$ omni signin
signed in by OMNI_TOKEN as ada — vertuoza/vertuo-omni-loop goes to vertuoza

Every command that talks to the Omni page signs in from the token, with no browser.

2. Making the token

Today 
$ omni setup-token
omni: unknown command setup-token

The only sign-in is the laptop's ~/.config/omni/credentials.json. Copying it elsewhere breaks both copies at the first renewal.

After 
$ omni setup-token --name claude-cloud
Sign in in your browser: https://www.omni-loop.xyz/ask/signin?purpose=token&…
token claude-cloud made · expires 9 Jan 2027
omk_Q3vX…9fKa
Paste it as OMNI_TOKEN=<token> in your cloud environment's variables.

Or Make a token on your profile page (below). Either way: shown once, stored as a hash.

3. The exchange

Today
After

Only the server holds the rotating refresh token, so any number of sessions share one token, and the laptop's sign-in is untouched.

4. When the token stops working

OMNI_TOKEN expired on 9 Jan 2027: make a new one with omni setup-token
OMNI_TOKEN was revoked: make a new one with omni setup-token
OMNI_TOKEN: ada is no longer a member of vertuoza
OMNI_TOKEN: cannot reach www.omni-loop.xyz: allow it in your environment's network access

What stays the same

On a laptopomni signin and credentials.json work as today, with OMNI_TOKEN unset.
Business links (PRD 855)Still read-only, still omb_, still no expiry; a business link never signs the kit in.
GitHubUnchanged: a cloud session reaches it through Claude's GitHub connection.
