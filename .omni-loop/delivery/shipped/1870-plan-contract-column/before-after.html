PRD 1870 — A plan declares the contract each slice changes

Nothing on a screen changes. What changes is one column of a plan's slice table, one key of a repository's config, what omni plan check refuses, and which targets a plan repository copies the planning config of. Today beside after, on the case that found the gap: PRD 229's plan in nimbus-plan.

1. The slice table

Today

| id | repo               | slice                                | territory                                  | blocked by | wave |
| --- | ------------------ | ------------------------------------ | ------------------------------------------ | ---------- | ---- |
| s1 | nimbus-backend-php | the kernel renders the mail types… | `packages/services/kernel/src/graphql/…`   | —          | 1    |
| s2 | nimbus-apps        | the V3 page lists the templates…   | `apps/nimbus-front/src/views/…`            | s1         | 2    |
| s4 | nimbus-backend-php | the kernel creates and edits…      | `packages/services/kernel/src/usecases/…`  | s1         | 2    |

What s1 and s4 change for their callers is in the "done when" prose, three screens down. A machine cannot read it; a reviewer may miss it.

After

| id | repo               | slice                                | territory                                  | contract | blocked by | wave |
| --- | ------------------ | ------------------------------------ | ------------------------------------------ | -------- | ---------- | ---- |
| s1 | nimbus-backend-php | the kernel renders the mail types… | `packages/services/kernel/src/graphql/…`   | api      | —          | 1    |
| s2 | nimbus-apps        | the V3 page lists the templates…   | `apps/nimbus-front/src/views/…`            | —        | s1         | 2    |
| s4 | nimbus-backend-php | the kernel creates and edits…      | `packages/services/kernel/src/usecases/…`  | none     | s1         | 2    |

A column read by its name: one or more of the receiving repository's kinds (api, db, api, db by default) or none on every slice of a repository that asks; — on the others. s4 changes nothing for its callers and now says so.

2. The repository that receives the slice asks

Today

# nimbus-backend-php/.omni-loop/config.yml
flow:
  areas:
    migrations:
      paths: ['^packages/services/kernel-migrations/', …]
      rules: { plan: [ { slice: { alone: true } }, { landing: alone } ] }

The back-end already writes the rules of its own paths. No key says "my slices declare their contract".

After

# nimbus-backend-php/.omni-loop/config.yml
flow:
  areas:
    migrations: …
contracts:
  declare: true
  kinds: [api, db]   # optional, the default

One boolean, false by default, and the repository's own kinds, [api, db] by default: a worker could name [api, event], with no kit release. Any plan that lands a slice here, from any plan repository, then declares. The plan repository lists nothing.

3. What omni plan check says

Today

$ omni plan check 229
waves: 1 → s1, s3 · 2 → s2, s4, s5 · 3 → s6, s7
collisions: none
ok

Green, with two backend slices that add mutations and one that adds a query, none of it visible here.

After

$ omni plan check 229
waves: 1 → s1, s3 · 2 → s2, s4, s5 · 3 → s6, s7
collisions: none
contracts: s1 api · s6 api
s4: contract: declares nothing — api, db or none
not ok

The planner's "check until green" step fixes s4 before the plan is pushed. A word outside the repository's kinds is refused the same way: s3: contract: "graphql" is no kind of this repository — api, db or none.

4. How a plan repository knows what a target asks

Today

.omni-loop/knowledge/repos/
└── nimbus-apps/            knowledge: imported
    ├── playbook/ …
    └── flow/config.yml     ← its planning config, copied

(nimbus-backend-php is knowledge: own → no folder, nothing copied)

Only an imported target's planning config reaches the plan repository. An own target's flow areas and landings.alone are never read by plan check here.

After

.omni-loop/knowledge/repos/
├── nimbus-apps/            knowledge: imported
│   ├── playbook/ …
│   └── flow/config.yml
└── nimbus-backend-php/     knowledge: own
    └── flow/config.yml     ← flow, landings, pr, contracts — and nothing else

$ omni targets
nimbus-backend-php  back-end  own  v0.0.395  stale (flow not copied)   ← until mega-invade --sync

Every target's planning config is copied, own and none included; a knowledge base is still never copied unless imported. omni targets says when a copy is missing or behind; --sync redraws it.

What stays the same

  • A plan with no contract column is graded as it always was wherever no repository asks; existing plans are not backfilled.
  • Waves, collisions, blockers, landings, flow areas: unchanged. The column is invisible to every rule but its own.
  • Nothing in the kit acts on the declaration: no merge-time check, no label, no comment. Downstream gates read Slice.contract.
  • A target's knowledge base is copied only when imported; own stays read where it lives.
