PRD 2915: before and after

galaxy

Functional

An owner attached the workspace's own GitHub App, here acme-bugs, to an API key on Settings › API keys. Their tool sends a bug fix through the public API with that key.

Today

The fix runs as the Omni App. Everything the job writes on GitHub reads omni-loop-invader[bot], though the key holds its own App: that App is kept, and never used.

On Settings › API keys, the key's last token date stays where it stopped.

At send, a bug fix is checked against the key's App on its repository. A mega bug fix is checked only on its plan repository, though its job reaches every repository of the product.

After

The fix runs as the key's own App. Everything the job writes on GitHub reads acme-bugs[bot]. A job sent from the Omni page, or by a key with no App, still runs as the Omni App.

When the key's App cannot open a token, the job fails before a runner starts it and says why, as in github app: the App is not installed on acme/web. It never runs as the Omni App or as a person instead.

The key's last token date moves at every token its App opens.

A mega bug fix is checked at send on every repository of its product the key may reach. The first one the App cannot work on is named in the refusal, and nothing is queued.

Flow

Deploy order

  1. Before the merge, by hand: each owner whose API key holds a GitHub App checks that the App is installed, with write access to contents, pull requests and issues, on every repository its jobs reach (for a mega bug fix, every repository of its product in the key's allow-list). From the deploy on, a job still queued runs as the key's App at its next token.
  2. galaxy: one deploy carries the mint, the refresh, the send check, the API description and the guide together.
  3. database and kit: nothing ships. No migration, no kit release.

Rollback: revert the merge. Every job takes the Omni App again at its next token.

Behaviour

Today

tokenFor() mints every job from the Omni App (GithubDeps.credentials). reachOf() reads appOfJob() only to refuse a stopped key and to read the allow-list: the key's own App is never read.

api_key_github_app_minted() is never called.

startMegaBugFix() runs appRefusal() on the plan repository alone.

After

tokenFor(), at claim and in githubToken, takes the key's App when appOfJob() answers an App (working, or needs_app): it opens the sealed key (GithubDeps.master, GithubDeps.open), mints on its installation for reachOf()'s repositories, and answers the bot stored with the App. Otherwise the Omni App, as today.

Each mint of a key's App calls api_key_github_app_minted(); a record that fails still answers the job.

startMegaBugFix() runs appRefusal() on each repository the job's token would reach, when the key holds an App.
