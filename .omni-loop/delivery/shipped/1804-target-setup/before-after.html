PRD #1804 · before / after

Targets declare a setup command, run before their preflight

What a target slice of /omni:ultra-yolo runs, today and after. The change is to the config and to the words of the multi-repository skills; no screen changes.

Functional

The target's committed config

Today 
commands:
  preflight: pnpm test

One command the kit may run. There is no place to say how to install.

After 
commands:
  setup: pnpm install --frozen-lockfile
  preflight: pnpm test

An optional setup, committed by the target's team. omni init proposes it from the lockfile.

A slice in a fresh worktree of the target

Today
$ pnpm test sh: vitest: command not found # red for want of an install # "never install in a target": named as a human step, CI decides
After
$ pnpm install --frozen-lockfile Done in 9.8s $ pnpm test Test Files 42 passed (42) # the preflight is a real local check again

When the install itself fails

Today

Nothing installs, so the preflight is red for every target that needs dependencies.

After
$ pnpm install --frozen-lockfile ERR_PNPM_OUTDATED_LOCKFILE # slice stuck, the failing line quoted; no fix attempt spent, # the target is never edited to make its install pass

The rule the skills state

Today

"The one command ever run beyond git and gh is its own committed preflight."

After

"The only commands ever run beyond git and gh are its own committed setup, then its own committed preflight."

What stays the same

  • A target without setup runs its preflight alone, as today.
  • A target without a preflight runs nothing, its setup included: CI is its check.
  • Both commands are read from the target's default branch, never from a slice branch or an imported playbook copy.
  • The kit's own-repository flows (/omni:wave, /omni:bug-fix, /omni:do-work without --target) are untouched.
