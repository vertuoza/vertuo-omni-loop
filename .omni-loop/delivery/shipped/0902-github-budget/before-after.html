Call GitHub only when needed

PRD 902. Galaxy and omni-app share one GitHub budget per installation. Today they spend it blindly: no ETags, no idea of what is left, and full re-reads of PRDs that did not change. After: one shared client that knows the budget, pages that render from a Supabase snapshot, and webhooks that say what changed.

2. What a change on GitHub costs

Today
TriggerGitHub calls
Stages sync, every 15 min, for each PRD in building or outbox, changed or not13 + N
Each forwarded stage event (a slice merges)13 + N
A PRD page on a cold server instance13 + N
An issue comment, a push, a reviewnothing hears it

N is the number of outbox item files. Every answer counts against the limit, unchanged or not, and the three triggers never share a cache.

A 304 Not Modified does not count against GitHub's limit. ETags live in Supabase, so every server instance of both apps shares them.

4. What stays the same

  • What the PRD and fix pages show: the same tabs, the same outbox, pull requests and checks, now with "GitHub as of HH:MM".
  • The stage events and the 15-minute sync keep running. The sync becomes the safety net for a webhook that never arrived.
  • Calls made with a person's own token (sending outbox answers, sign-in) and the App's token minting are untouched.
  • omni-app's checks post what they post today. They now ask GitHub through the shared client.
  • The App asks for no new permission. An org admin ticks five more events in its settings once.
