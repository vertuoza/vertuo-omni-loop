PRD 976 · Type-aware linting at zero, on a suite that holds under load

Nothing on screen changes. What changes is what a pull request is checked for, and that the suite stops failing when the machine is busy.

Today

A promise handed to a callback that ignores it

button.addEventListener('click', async () => {
  await save(draft);       // a rejection goes nowhere
});
$ pnpm typecheck
✓ no error          the compiler cannot see it

A value printed as "undefined"

line = `PRD ${prd.title}`;   // title: string | undefined
→ "PRD undefined" in a comment on GitHub

A ! that claims a value is there

const first = rows[0]!.id;  // TypeError three calls later

A busy machine turns slices red

kit/bin/ask-hook.test.ts
  one Node process per hook kind × input, in sequence

No linter

checks: test · typecheck · fallow

After

The linter names it before review

$ pnpm lint
✗ save.ts:12  Promise-returning function provided to
  attribute where a void return was expected
  (@typescript-eslint/no-misused-promises)

The string says what it means

line = `PRD ${prd.title ?? '(no title)'}`;
✓ restrict-template-expressions

A missing value is named where it is missing

const first = at(rows, 0, 'the first row').id;
→ "the first row is missing", here, not later

The suite holds under load

kit/bin/ask-hook.test.ts
  the matrix runs in process, through main()
  one real process per behaviour only a process proves
✓ passes beside a second full pnpm test

A lint job, at zero, nothing silenced

checks: test · typecheck · fallow · lint
0 findings · eslint-disable: refused by the guard, inert in the config

What stays the same

  • Every command, page and output: the suite pins behaviour, with at least as many tests as before.
  • Formatting: the linter checks meaning, not layout.
  • The bundle other repositories run, .omni-loop/bin/omni.mjs: same name, same commands.
  • Every check a value needs at runtime: none is deleted on the type's word alone.
