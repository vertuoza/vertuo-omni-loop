Hook-free omni commands

PRD #1831 · Architectural · first of four PRDs toward a kit any coding agent drives. Every job Claude's hooks do becomes an omni command any agent runs from a shell, on a laptop or in a cloud session (Claude Code on the web, Codex on chatgpt.com). Claude keeps its hooks, unchanged.

2 · An agent asks a question

Today

Claude calls AskUserQuestion
the hook reads stdin + Claude's transcript, posts the round, waits up to 540 s
the answer comes back as the tool's input
Codex, Cursor, Gemini CLI, a cloud session without the plugin: the page is never reached; the question stays in the terminal

After

$ omni ask question --file q.json      # AskUserQuestion's shape
                                       # + optional lead, context
exit 0  {"round":"r_8f…","answers":{…},"shots":[…]}
exit 3  (stderr: ask mode is off)      → ask in your own chat,
                                         then omni ask answer
exit 4  round r_8f…                    → omni ask wait r_8f…
exit 2  q.json: questions[0].header is missing

Waits 110 s by default, under a cloud shell's 2-minute limit; --wait takes 10 to 540. Resume as often as you like.

3 · A session in the cloud

Today

  • OMNI_TOKEN signs omni in (PRD 1628)
  • ask mode needs .omni-loop/local/ask.json: a fresh clone has none
  • the hooks need Claude's plugin and its stdin; Codex on the web has neither
  • a 540 s wait outlives a 2-minute shell

After

# the cloud environment's variables
OMNI_TOKEN=omk_…
OMNI_ASK=on
# network access: allow the Omni page's host

$ omni session start      # constituents, briefing,
                          # session: 3c1e…
$ omni ask question --file q.json
$ omni session end

Nothing reads stdin, needs a TTY or ~/.config/omni. An unreachable page is exit 3: the agent asks in its chat, as today.
