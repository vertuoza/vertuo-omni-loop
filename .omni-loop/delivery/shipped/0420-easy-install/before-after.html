The Install page of the Getting Started guide (/docs/install), today beside after. Node, git, gh and Claude Code become prerequisites you check, omni arrives with one npm line, and omni init does the chores.

Install

  1. Install Node 22 → prerequisite
  2. Install gh, gh auth login → prerequisite
  3. Install Claude Code → prerequisite
  4. git switch -c chore/install-omni-loop → init
  5. npx github:vertuoza/vertuo-omni-loop init
  6. Edit config.yml by hand (ask, dossier) → init
  7. add, commit, push, gh pr create, merge, pull → init
  8. Put omni on your PATH (13 lines) → npm -g
  9. Two /plugin commands in Claude Code → init
  10. Install the GitHub App
  11. omni signin → init
  12. Check: omni config, omni status, /omni:help

8 · Put omni on your PATH

terminalmkdir -p ~/.local/bin
cat > ~/.local/bin/omni <<'EOF'
#!/bin/sh
root=$(git rev-parse --show-toplevel 2>/dev/null)
if [ -z "$root" ] || [ ! -f "$root/.omni-loop/bin/omni.mjs" ]; then
  echo "omni: no Omni Loop kit here ..." >&2
  exit 2
fi
exec node "$root/.omni-loop/bin/omni.mjs" "$@"
EOF
chmod +x ~/.local/bin/omni
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
exec zsh

zsh only. Bash users are told to edit it by hand. Pasting it twice adds the PATH line twice.

1 · Install omni

terminalnpm install -g github:vertuoza/vertuo-omni-loop

Once per laptop. Works in zsh, bash and fish; no shell file is edited. Inside a repository, omni always runs that repository's own pinned copy.

2 · Install the loop in your repository

What stays the same

  • Every skill still runs node .omni-loop/bin/omni.mjs; the repository pins its version, and omni update keeps it current.
  • Nothing reaches the default branch unless a person merges it: init opens the install PR and stops.
  • Repositories installed before keep working as they are; an old ~/.local/bin/omni does no harm (Troubleshooting says how to remove it).
