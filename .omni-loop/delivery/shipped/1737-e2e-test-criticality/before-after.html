A test's criticality is decided by the critical flows it covers

PRD 1737 · settled before PRDs #1277, #1278 and #1279 of roadmap #1280

Today

  • Every PRD with e2e: validate adds tests; nothing says which ones matter.
  • All tests would run after each deploy, so the suite that blocks a deploy grows with every PRD.
  • omni e2e status only says whether a recording exists.

After

  • Each product lists its critical flows in <e2e.dir>/critical-flows.md, reviewed in a pull request.
  • The skill asks which flow a new test covers and whether its failure breaks it, then tags the test critical or leaves it standard.
  • Under /omni:yolo a test enters standard and the question is an outbox item.
  • omni e2e status shows each test's level and flow, and refuses a critical test with no known flow.
