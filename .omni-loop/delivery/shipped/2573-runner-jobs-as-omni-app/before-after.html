After
omni-loop-invader bot opened this pull request
s2: the billing service reads the new totals · sent from the Omni app by @sam-member

Commits by omni-loop-invader[bot]. Every member, Maya included, can review and approve it.

The same holds for a job an API key sent: it signs as the Omni bot, not as the key's own App. A job that cannot get the bot (the App missing on the repository, or a permission it lacks) ends Failed with that reason before it starts, and never runs under anyone's name.

Flow

Deploy order

  1. A person grants the Omni App workflows: write and each installation accepts it.
  2. The migration replacing runner_claim() (supabase workflow).
  3. The galaxy app (Vercel): every claim mints from the Omni App.
  4. The kit's release: runners refuse a job without github. Each runner box is reinstalled on it.
