PRD 2850: before and after

kit

Functional

Today
  • The page has two tabs. The screens of a change sit inside the first one, as small cards, one group per service.
  • A reader cannot name a screen: a change is asked for as “the second card on the right”.
  • The author first sees the page once it is committed and pushed. The brainstorm is told never to show it in a private page.
After
  • The page has three tabs: Functional, Technical, Pixel perfect.
  • Pixel perfect shows every screen the change touches whole, at its real width, inside its app shell, today beside after.
  • Every screen has a number and every state a letter. “2.C” means the same state of the same screen in every version.
  • With an agent that can publish a private page (in Claude: an artifact), the author sees the page first and chooses Iterate or Carry on. What they last saw is what is committed.
  • With another agent, or on a runner, nothing changes.

The first look, as an exchange

Today

Agent

Writes the page, grades it, commits it, pushes it to the PRD’s page.

Author

Opens the PRD’s page, finds what to change, asks for a rework.

After

Agent

Writes the page, grades it, publishes it privately.

“Here is the before/after: <private link>. Iterate, or carry on?”

Author

“Iterate. 2.C: shorten the error. Everywhere: the header one step darker.”

Agent

Changes the file, grades it again, republishes to the same link, asks again.

Author

“Carry on.”

Agent

Writes the exported page as the file, grades it once more, commits it. The link is stored nowhere.

Flow

Deploy order

  1. kit, in one feature PR: the template, the skeleton and the grader first, then the skills and the guide, then the rebuilt kit/dist/.
  2. No migration, no API, no deploy of the arcade or the GitHub App’s data. A repository gets the change at its next kit update.

Behaviour

Today
  • The grader accepts a filled Pixel perfect section that holds anything, cards included.
  • The brainstorms (/omni:brainstorm step 5 and Rework, /omni:mega-brainstorm step 6) write the page, grade it and commit it; they are told never to publish it as a private page.
  • /omni:do-work and /omni:pr read the screens: line in the Pixel perfect section of the Functional tab.
After
  • The grader, on a version 3 page, refuses: a missing tab; a screen outside the Pixel perfect tab; a filled tab with no screen; a screen with no reference, side or width; a reference and side written twice; a reference with no “after”; a number that names two screens; a screen the screens: line does not name.
  • The brainstorms draw whole, numbered screens, then show the graded page to its author first when the agent can and the run is attended, and commit the export once it is graded again.
  • /omni:do-work and /omni:pr read the same line in the Pixel perfect tab, in either shape.
  • The word pass reads marked screens as today; a frame’s caption is not part of a screen.

screens: prd-dossier · before-after-page · app-shell
