PRD 2871: before and after

kit

Functional

Today

Under a mission, the Engineer's /omni:yolo builds the PRD, ships it and marks its feature PR ready on its own word. No agent but the one that built the branch has looked at it before a person is asked to review. The Reviewer hero has no skill.

After

A new skill, /omni:review <n>, reviews the branch like a person: one GitHub review on the feature PR, one thread per finding on its line, each citing the rule it breaks (the spec, a law, a playbook section, or the kit's default). No finding: it marks the PR ready. One to five findings: it hands them back. At most two rounds, then a person decides.

What it looks for is a good default (correctness, security and data, tests that prove it and none loosened, scope, laws and conventions, design only as a defect) that the repository extends in its playbook's review › look-for, never shortens. A second agent tries to disprove each finding before it is posted.

Under a mission, /omni:yolo and /omni:yolo-fix stop before ready and hand the PR to the Reviewer. Outside a mission, nothing changes.

omni-app

Functional

Today

A mission sends /omni:yolo for a PRD; when the job ends ready, the PRD waits for a person to merge it.

After

A mission sends the build, then the Reviewer as its own job; on findings, the Engineer's /omni:yolo-fix, then a second review. After two rounds that still disagree, the PRD waits on a person: decide the Reviewer's findings on PR #2817. Each review and fix is sent once, whatever replays.

database

Functional

Today

A job ends as answers, held, ready, a person needed, or stopped. A mission's log has no row for a review.

After

A job may also end as waits for review or changes asked; the mission's log records each verdict, signed by the Reviewer as an agent; the Reviewer hero of every Virtual Fleet gets its skill and its limits.

galaxy

Functional

Today

The Heroes tab reads the Reviewer as A person does this today: its review skill is not built yet. The Operation room has no Reviewer row.

After

The Reviewer reads Works alone, runs /omni:review, with its four limits. The Operation room ledger shows each verdict as a Reviewer · agent row linking the review: Changes asked: 2 findings, round 1/2.

Flow

Under a mission (each arrow a runner job the supervisor sends once, under its own key):

supervisor ── /omni:yolo n --for-review ──▶ Engineer   builds, gate, omni ship, PR stays draft → ends reviewsupervisor ── /omni:review n ──────────────▶ Reviewer   reads spec · plan · laws · playbook · default look-for                                                       drafts findings → verifier tries to disprove → ≤ 5 kept                                                       posts one GitHub review (COMMENT, a thread per finding)   pass    → yolo.ready hooks · gh pr ready · CI          → ends ready  → waits for a person's merge   changes → ends changes, round 1 → supervisor sends /omni:yolo-fix n --for-review (Engineer)             fix / push back / ask on each thread, omni ship → ends review → /omni:review n, round 2   changes, round 2 → the PRD waits on a person; no round 3

Datastores: Omni's database (runner_jobs, mission_events, virtual_heroes); third party: GitHub (the review, its threads, the PR's ready state).

Deploy order

  1. database: the migration (outcome check, event kind, the Reviewer's defaults), first: it only widens checks, so today's code keeps working.
  2. kit: /omni:review, --for-review, the hand-offs and the look-for section, released with the kit.
  3. omni-app: the supervisor's hand-offs, last: only then do missions send Reviewer jobs.
  4. galaxy: the room's reviewed rows, any time after the migration.
