TODAY

A PRD's page says which stage it is in: the pills light up to the current one. It never says when a stage was reached, how long a step took, or who it waited on. The Engineering board times pull requests, not a PRD's steps.

AFTER

Under the stage, one line says how long the PRD took from idea to merged and which step was the longest (or, while it is built, how long it has run and which step it is in). A Timeline tab lists each milestone with its date, and each step between two with its duration and who it waited on: an approver, the agents, the outbox answers, a reviewer. A PRD landing in several repositories shows one lane per repository. The Engineering board gains Time per step: the median of each step over the PRDs done in the period, and the slowest step named.

supabase

Functional

TODAY

The database keeps when each PRD reached each of its six stages, nothing finer, and nothing per repository.

AFTER

It also keeps each PRD's milestones (idea, plan, approved) and, per repository it lands in, when its feature PR opened, its first and last slice merged, it was marked ready and it merged. Only the workspace's members read them.

Flow

Deploy order

  1. supabase: the migration adding prd_milestones, its trigger and its policies (applied by the supabase workflow on merge).
  2. galaxy: the sync writing it and the views reading it, deployed by the release commit. A sync that runs before the migration applies fails its milestone write only, and logs it; the stages still sync.
