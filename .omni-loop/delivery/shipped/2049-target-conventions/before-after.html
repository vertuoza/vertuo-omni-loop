Brainstorms and plans follow each repository's written conventions

Functional part only. Replayed on the case that started it: PRD 278 of nimbus-plan, adding timestamps to nimbus-backend-php's avancement table.

Functional

What /omni:mega-brainstorm reads in a target before it names a column, and what the spec says about it.

2. The name the spec picks

Today

ALTER TABLE avancement
  ADD created_at …,
  ADD updated_at …

The spec saw that updated_at and _updated_at coexist, and chose without a source. A reviewer corrected it in five comments.

After

ALTER TABLE avancement
  ADD _created_at …,
  ADD _updated_at …

docs/migrations.md: "Note the underscore prefix (_created_at, not created_at)." Two conventions with no page to settle them become a question to the person, never a silent pick.
