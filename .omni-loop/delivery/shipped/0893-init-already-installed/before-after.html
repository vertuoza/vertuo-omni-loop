PRD 893 · before / after

omni init on a repository that already runs the loop

Today every run goes through the install branch and tries to open the install pull request. After this change, a repository whose main already has .omni-loop/config.yml only gets this computer set up: the plugin and the sign-in.

1. Installed on main, not invaded yet

A teammate clones the repository after the install PR merged and runs init to get the plugin.

2. Installed and invaded

A playbook form on main says state: filled, invaded: 2026-09-25.

What stays the same

  • First installunchanged No config on main: the install branch, the files, the labels and the install PR, as today.
  • --forceunchanged Always a full reinstall through chore/install-omni-loop and its PR.
  • No remote, or git cannot read mainunchanged Nothing is detected, so today's flow runs.
  • Exit codeunchanged Init still exits 0, and a failed step is still a line, never a crash.
