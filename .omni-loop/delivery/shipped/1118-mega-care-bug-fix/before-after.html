Mega PR care and mega bug fix

PRD #1118. Two commands for a plan repository: /omni:mega-pr-care <n> looks after every pull request of a multi-repository PRD, and /omni:mega-bug-fix fixes a bug across the targets that hold it. The example: plan repository vertuo-automation-plan, targets vertuo-backend-php (back-end) and vertuo-apps (front-end).

After /omni:ultra-yolo

Ultra-yolo leaves one PR per target plus the plan PR. Today nobody looks after them; the front-end PR burns its fix attempts on a red caused by the back-end PR not being merged yet.

A bug across repositories

The front-end shows it, the cause is in the back-end. One issue in the plan repository, one fix plan, the provider first, one linked PR per target, and one record PR that closes the bug, merged last.

What stays the same

  • /omni:pr-care and /omni:bug-fix are unchanged, and so is the PRD page: it reads the plan PR's care line.
  • In a target, nothing runs but its own committed preflight. No label is ever created there.
  • Nothing merges by itself, and nothing is marked ready. A person merges every PR.
  • A fix that would break today's front-end, a database change or a new screen still goes to /omni:mega-brainstorm.
