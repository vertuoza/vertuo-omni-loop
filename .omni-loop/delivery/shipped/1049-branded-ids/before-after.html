PRD 1042 · A feedback loop in seconds

PRD 1049 · Branded IDs

Nothing on screen changes. What changes is what the compiler refuses when an agent mixes up two identifiers.

Today

Every ID is a bare number or string

function postOn(prd: number, …)
function commentOn(issue: number, …)
type PrdNumber = number | string   // looser than number

const pr = 1043
postOn(pr, …)          // compiles: wrong folder, wrong issue

Ids read from files

slice: 'S1'            // accepted; fails three calls later
/^(\d{4})-(.+)$/       // the folder regex, three copies

Nothing keeps it so

prd: number            // a new function, any day

After

One brand per kind, made only by parsing

import { parsePrd, type PrdNumber, type PrNumber } from 'kit/lib/ids'

function postOn(prd: PrdNumber, …)
function commentOn(on: IssueNumber | PrNumber, …)

const pr: PrNumber = parsePr(1043)
postOn(pr, …)          // error: PrNumber is not PrdNumber
commentOn(prd, …)      // fine: a PRD is its issue

Ids read from files

slice: 'S1'            // refused where the plan is read
parsePrdFolder(name)   // one regex, one place

A guard keeps it so

prd: number            // id-types guard: use PrdNumber

What stays the same

  • Behaviour, command output, stored data and wire formats: a brand is the same number or string at run time.
  • The no-as guard: a brand is made by zod parsing, never by a cast.
  • Branch names and the bare field name number stay as they are; the environment variables get their own PRD next.
