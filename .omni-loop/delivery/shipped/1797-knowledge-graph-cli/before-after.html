PRD 1797 — before and after

PRD 1797 · P5 of the roadmap "Governed knowledge"

The knowledge graph from the CLI: omni kb graph <id> prints one entry's neighbourhood, one line per node, never a whole register.

Functional

1 · Asking about one rule

Today

$ omni kb graph BR-PRODUCT-3
usage: omni kb graph [--json]
exit 2

$ omni kb graph
kb graph — 1 domain, 189 entries, 96 links
  product    81 principles · 96 rules · 12 invariants …
  loose entries (12): N-PRODUCT-2, N-PRODUCT-3, …

An id is refused. The only answer is the whole folder: a summary, or 124 KB of JSON with two link kinds, serves and cites.

After

$ omni kb graph BR-PRODUCT-3
BR-PRODUCT-3 · rule · law, locked by @pierrederval — When the
  only red check is the outbox context …, /omni:pr reports this
  in the status comment and stops.
  up    serves       P-PRODUCT-3                    principle  The outbox gate stays red …
  down  enforced-by  test:kit/test/plugin.test.ts   test
  down  governs      path:^kit/plugin/skills/(pr)/  path
  down  governs      path:^kit/test/plugin\.test\.ts$  path
  side  same-prd     ADR-0006                       adr        Without a named summary check …
  side  same-prd     ADR-0007 … ADR-0011            adr        (five lines)
  side  same-prd     … and 3 more (--json lists them all)
product knowledge: offline — no cached copy of the product's
  Legal and Glossary; only this repository's links are shown.

Up, down and sideways from one entry, at most 6 lines per edge kind. The last line always says where the Legal and Glossary nodes stand.

2 · Asking about a file

Today

$ omni kb laws --paths kit/lib/board.ts
law BR-PRODUCT-3 — An agent never applies the override label …
law …                         (every locked law)
rule BR-PRODUCT-2 — When a pull request's head commit date
  cannot be read, the claimed-stale check …

The rules that govern the file, as headlines. Nothing says what proves them, what they serve, or which decision records and screens sit beside them.

After

$ omni kb graph --paths kit/lib/board.ts
BR-PRODUCT-2 · rule — When a pull request's head commit date
  cannot be read, …
  up    serves       P-PRODUCT-2              principle  …
  down  enforced-by  test:kit/lib/board.test.ts  test
  down  governs      path:^kit/lib/board\.    path
  side  same-prd     ADR-0006                 adr        …
  …
product knowledge: cached 2026-10-12 (omni).

$ omni kb graph BR-PRODUCT-2 --depth 2 --json

One block per entry whose Governs: matches, laws first. --depth walks up to 3 hops between entries; --json gives agents every node.

4 · What stays the same

Today

omni kb graph and omni kb graph --json print the whole folder; the arcade's knowledge map reads that JSON (version: 1).

After

Unchanged. The neighbourhood is a second shape, {"version":1,"shape":"neighbourhood","start","depth","product","nodes","edges"}, the contract the server API (P6, #1798) publishes as is. The command reads the product cache and never calls the network.

Pixel perfect: no screen changes
