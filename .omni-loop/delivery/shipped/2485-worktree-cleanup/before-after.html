PRD 2485: before and after

kit

Functional

Today

Every slice of a wave is built in its own worktree under .claude/worktrees/, a full copy of the repository with its own node_modules. Nothing ever removes it: after a few yolos a developer's disk holds dozens of them (about 186 GB on one laptop), and the feature worktree of each brainstorm stays too.

The person who notices a full disk deletes folders by hand, with no way to tell which still hold work that was never pushed.

$ git worktree list…/vertuo-omni-loop                      [main]…/.claude/worktrees/agent-a1f3          [feat/quotes--s1]…/.claude/worktrees/agent-b72c          [feat/quotes--s2]…/.claude/worktrees/agent-c09e          [feat/quotes--s3]…/.claude/worktrees/quotes              [feat/quotes]… 40 more
After

Once the wave merges a slice's sub-PR, it removes that slice's worktree. At the end of the yolo, the PRD's leftovers go too: the merged slices' worktrees and its feature worktree. A red, stopped or blocked slice keeps its worktree, so someone can see why it failed, and the hand-off names it.

Nothing that is uncommitted, unpushed, in use or not the kit's own is ever removed. omni worktrees prune --dry-run shows what would go, and when a session starts one line says when there is something left to clean.

Deploy order

One release of the kit: kit/dist/omni.mjs rebuilt with the command, the three skills and the hook in the same release. A repository starts cleaning once it runs omni update. No migration, no server change.

Behaviour

Today

/omni:wave merges a sub-PR and moves on; /omni:yolo hands off; the slice and feature worktrees stay on disk forever.

After

/omni:wave step 4 and Inline wave run omni worktrees remove after each merged or done slice and report its line; /omni:yolo and /omni:yolo-fix run omni worktrees prune --prd <n> before their hand-off, which names each kept worktree with its path and reason.
