Runners: send work from the Omni app to a terminal

PRD 1830. A server running omni runner shows up on a new Runners page. A line the app lets you copy can be sent to it instead, and the job's log and pull request come back to the app.

Functional

How a command gets run

Today
  1. On a PRD's page, Build it copies /omni:yolo 1717.
  2. You open a terminal on a computer with the repository, Claude Code and its sign-ins.
  3. You paste it, or SSH to the agent box and type yolo 1717.
  4. The app never sees the run: no log, no state, no link to the pull request until it shows on GitHub.
After
  1. Send to terminal beside Build it. Pick a fleet or a runner, then press Send. app → runner_jobs: queued
  2. A free runner you may use claims it from its open next call. for update skip locked · claimed
  3. It runs the line in a worktree, in tmux job-<id>, and sends the last log lines every 5 s. running
  4. It ends Done with the pull request's link, or Failed with why. You can cancel at any time. done · failed · cancelled

Who talks to whom

Today
  • Terminals push their status to the app (working_pings, one per Claude session).
  • Terminals ask the app for answers (/api/ask/rounds/<id>/wait) and approvals.
  • The app sends a terminal nothing.
After
  • POST /api/runners/register: name, slots, repositories, kit version.
  • GET /api/runners/next: a check-in that holds up to 50 s and answers a job or 204. Outbound only, so no port opens on the server.
  • POST /api/runners/jobs/<id>: status, log tail, PR link. It answers {cancel: true} when a cancel waits.
  • Only the lines /omni:yolo · yolo-fix · pr-care · do-work · wave · bug-fix · visual-fix · plan · pitch · prove, checked by the app and again by the runner.
  • A runner silent for 90 s: its jobs become Failed, runner lost, and nothing is retried by itself.
