omni runner hands the Claude token to its jobs

PRD 1894. A server signed in with claude setup-token sets CLAUDE_CODE_OAUTH_TOKEN. Today the runner does not pass it to the tmux session each job runs in; after, it does.

Functional

Today 
# the runner starts with the token set
CLAUDE_CODE_OAUTH_TOKEN=sk-ant-oat01-… omni runner …

# each job's session gets
tmux new-session -d -s job-<id> \
  -e PATH=… -e OMNI_TOKEN=… \
  node omni runner job …

# the job's log
Failed to authenticate: OAuth session
expired and could not be refreshed

The token stays with the runner. The job falls back to Claude's stored sign-in, and fails once that expires. The start script works around it with tmux set-environment -g.

After 
# the runner starts with the token set
CLAUDE_CODE_OAUTH_TOKEN=sk-ant-oat01-… omni runner …

# each job's session gets
tmux new-session -d -s job-<id> \
  -e PATH=… -e OMNI_TOKEN=… \
  -e CLAUDE_CODE_OAUTH_TOKEN=… \
  node omni runner job …

# the job's log
claude signs in with the token and runs the line

Read once, in the kit's env module, as vars.claudeToken. Unset, nothing changes. ANTHROPIC_API_KEY is never passed.
