# Install for any coding agent

**Date:** 2026-10-14 · **PRD:** #1890 · **Touches:** `kit/lib/config.ts`, `kit/bin/commands/init.ts`,
`kit/lib/init/`, `kit/lib/update/`, a new `kit/lib/agents/`, `kit/build.ts`, `kit/bin/commands/check.ts`,
`kit/lib/help/`, `.omni-loop/knowledge/product/invariants.md` (N-PRODUCT-13), the rebuilt `kit/dist/`
· **Kind:** Architectural

## Problem

PRD 1831 made every hook's job a plain `omni` command, and PRD 1858 made every skill's words
followable by any coding agent. The install still serves Claude Code alone:

- `omni init` installs the skills through `claude plugin install omni@omni-loop`
  (`kit/lib/init/plugin.ts`), and `omni update` refreshes them through `claude plugin update`. A
  teammate on Codex, Cursor or Gemini CLI gets no skill at all.
- Codex, Cursor and Gemini CLI all read a repository's skills from `.agents/skills/<name>/SKILL.md`
  ([Codex](https://developers.openai.com/codex/skills), [Cursor](https://cursor.com/help/customization/skills),
  [Gemini CLI](https://geminicli.com/docs/cli/skills/), read 2026-10-14). Cursor requires the folder's
  name to equal the skill's `name:`. Nothing of the kit writes there.
- The config has no word for which agents a repository uses (`ConfigSchema` is strict).
- `omni help` lists the skills under "IN CLAUDE (type these)", as `/omni:yolo <n>` and
  `/loop /omni:drive`: forms only Claude Code takes.
- Locked law N-PRODUCT-13 reads: "omni init writes no file outside .omni-loop/ except two keys of
  .claude/settings.json, the status line and the band's setting, and never changes a value someone
  else set". Writing `.agents/skills/` breaks it as it stands.

## Solution

### 1. The config key `agents`

`agents: [<agent>, …]`, each one of `claude`, `codex`, `cursor`, `gemini`, at least one, no
repeat; default `[claude]`, so a repository that never sets it sees no change. `omni check config`
refuses an unknown agent, naming it. `omni config agents` prints it.

- `omni init --agent <agent>`, repeatable, sets it. Without the flag, a terminal init asks which
  agents the team uses (a multiple choice, Claude ticked); a non-interactive init writes the default.
- A repository already installed adds an agent by editing the key, then `omni update` (or
  `omni init --force`).

### 2. The skills ride in the bundle

`kit/build.ts` embeds every file under `kit/plugin/skills/` (768 KB today) in `kit/dist/omni.mjs`,
so the skills a repository gets are always the version of its bin, offline. `kit/test/dist.test.ts`
proves every file is carried byte-identical.

### 3. The writer: `.agents/skills/omni-<name>/`

A new module, `kit/lib/agents/`, run by `omni init` and `omni update` when `agents` lists any agent
but `claude`:

- For each skill `<name>`, it writes `.agents/skills/omni-<name>/SKILL.md`: the skill's front matter
  with `name:` rewritten to `omni-<name>` (the folder's name, as Cursor requires), then the line
  `<!-- generated by omni <version> from kit/plugin/skills/<name>; omni update rewrites it -->`, then
  the body byte-identical. Every sibling file (`pixel-perfect`'s `mock.md` and `reference/*.md`) is
  copied under the same relative path, unchanged.
- It records what it wrote in `.omni-loop/agents.json`: each folder it owns, each file's path and
  sha-256, and the kit version.
- It never writes or deletes a path outside the folders the manifest names. An `omni-*` folder that
  exists but is not in the manifest is someone else's: init and update stop on it, before writing
  anything, with one line naming it.
- `omni update` rewrites every owned folder from the new bundle, writes the skills new in this
  version, removes the owned folders of skills the version dropped, and updates the manifest.
- With `agents` back to `[claude]`, `omni update` removes the owned folders and the manifest.

When `claude` is listed, the Claude plugin is installed and updated, and `.claude/settings.json`'s two
keys written, exactly as today. When it is not, init and update touch neither.

### 4. The update PR says what changed

`omni update`'s pull request body gains a section **Skills for other agents**: one line per skill
whose copy changed (`omni-yolo: 3 lines changed`, `omni-think-big: new`, `omni-old: removed`), and
the sentence "these copies are generated from the kit; read the kit's release notes, not the
copies". No line when no copy changed.

### 5. `omni check agents`

A new check, in `omni check all`:

- **red** when an owned file's hash differs from the manifest (hand-edited) or is missing, or when
  `agents` lists a non-Claude agent and no manifest exists (not installed): each with the line
  `run omni update to rewrite the copies`;
- **green** otherwise, and when `agents` is `[claude]` with no manifest.

### 6. `omni help` shows each agent's form

`omni help` reads `agents` and gives each skill's usage in each installed agent:

| agent | form |
|---|---|
| `claude` | `/omni:<name> <args>` (drive: `/loop /omni:drive …`) |
| `codex` | `$omni-<name> <args>` |
| `cursor` | `/omni-<name> <args>` |
| `gemini` | `ask for omni-<name>, <args>` (it activates skills by description) |

The overview's heading "IN CLAUDE (type these)" becomes "Run these", each line one form per installed
agent; drive's non-Claude forms are its tick (`$omni-drive …`), with the line "run it again after the
wait it names". The status line and the HUD are Claude Code's alone: `omni help statusline` and the
init's closing steps say so in one line.

### 7. The law, amended

N-PRODUCT-13 becomes: "omni init and omni update write no file outside .omni-loop/ except two keys
of .claude/settings.json, the status line and the band's setting, and the `.agents/skills/omni-*`
folders the manifest says they own; they never change a value or a file someone else set, and they
commit .claude/settings.json whenever either key is the loop's." Its `Governs:` gains
`^kit/lib/agents/` and `^kit/lib/update/`; its `Enforced by:` gains the agents writer's test. Every
other line of its entry stays.

## Decisions

- **Amend N-PRODUCT-13, own `.agents/skills/omni-*`** (the person, owner of the law, over a
  user-level install the cloud sessions never get, or printing a command for a person to run).
- **A config key `agents` and a repeatable `--agent`** (the person, over writing the folders in
  every repository whatever its agents, or a flag init alone knows).
- **Embedded, generated, checked** (the person, over downloading from the release or symlinks that
  break on Windows and in some cloud checkouts): the bundle carries the skills, a manifest of hashes
  marks what the install owns, `omni check agents` flags a hand edit.
- **`omni-<name>`, the body unchanged.** The prefix keeps the kit's skills apart from a repository's
  own in a shared folder; only `name:` changes, as Cursor requires. A body's `/omni:<name>` is read
  through the briefing's **Any agent** section (PRD 1858).
- **One folder, `.agents/skills/`, for Codex, Cursor and Gemini CLI**: each reads it; no
  `.cursor/skills/` or `.gemini/skills/` copy.
- **The voice objected at the design** (persona:Lead Engineer): *"Every `omni update` PR will now
  carry 33 generated skill folders (persona:Lead Engineer); my reviewers will either skim them or
  waste time on them, and neither keeps the team in step."* Settled `accepted`: the update PR's
  **Skills for other agents** summary, and the generated line in every copy.
- **`blocked-by: [1858]`**: the copies are the reworded skills PRD 1858 shipped.
- **Proof video: no.** Nothing here shows in a browser.

## User stories

- As a developer on Codex, after `omni init --agent codex` and the install PR merged, I open the
  repository and `$omni-yolo 1890` runs the skill (persona:B-E DEv).
- As a PM in Cursor, `/omni-brainstorm` is there with every other omni skill, and stays at the kit's
  version after every `omni update` (persona:Irisa).
- As a team lead with Claude and Codex users, one key lists both, and `omni help` shows each person
  their own form (persona:Lead Engineer).
- As a reviewer of an update PR, one line per changed skill tells me what moved, without reading 33
  copies (persona:Lead Engineer).
- As a Claude Code user, nothing changes unless my team lists another agent (persona:F-E Developer).

## Scope

In: the `agents` key and `--agent`; the skills embedded by `kit/build.ts`; `kit/lib/agents/` (writer,
manifest, removal); init and update calling it, and the update PR's summary; `omni check agents` in
`omni check all`; `omni help`'s per-agent forms and the Claude-only line for the status line and the
HUD; N-PRODUCT-13's text, `Governs:` and `Enforced by:`; `docs/guide/install.md`'s agent choice; the
rebuilt `kit/dist/`.

Out: a step runner (PRD 4); copies under `.cursor/skills/`, `.gemini/skills/` or `.codex/skills/`;
installing for an agent per computer (`~/.agents/skills/`); rewriting `/omni:<name>` inside a copy's
body; this repository's own `agents` value (it stays `[claude]` until a person sets it).

## Test seams

As `omni kb show testing` says: vitest, temporary repositories, no network, no GitHub.

- **init:** for `[claude]`, `[codex]`, `[claude, codex]` and `[cursor, gemini]`, the written paths are
  exactly the expected ones: the `omni-*` folders and the manifest only when a non-Claude agent is
  listed, `.claude/settings.json` only when `claude` is. `kit/bin/init.test.ts`'s snapshot and its
  "writes nothing outside" assertion gain the exception, and no other path.
- **Foreign files:** a repository skill `.agents/skills/my-skill/` and any other file there stay
  byte-identical; an `omni-x` folder not in the manifest stops init and update, naming it, with
  nothing written.
- **update:** it rewrites a changed skill, adds a new one, removes a dropped one, removes all when
  `agents` returns to `[claude]`, and writes the PR body's summary lines (none when nothing changed).
- **The copies:** each `SKILL.md`'s `name:` equals its folder; the body after the generated line is
  byte-identical to the kit's; `pixel-perfect`'s relative links resolve inside its copy.
- **`omni check agents`:** green, hand-edited, missing, listed but not installed.
- **help:** each agent's form for a skill and for drive; the overview heading; the status line's
  Claude-only line.
- **The bundle:** `kit/test/dist.test.ts` finds every skill file carried byte-identical.
- **The law:** `kit/lib/init/settings.test.ts` and `kit/bin/init.test.ts` pass with the amended

## Risks

Merging publishes the kit on `main`; the release workflow's version commit follows. A repository
changes only when it lists a non-Claude agent and runs `omni update` or `omni init`. Rollback:
revert the merge; a repository that already installed keeps its committed `omni-*` folders and
manifest until a person deletes them (or sets `agents: [claude]` on a kit that still has the
writer and runs update).

- **The amended law** is the largest change: the install now writes outside `.omni-loop/`. The
  manifest, the stop on a foreign `omni-*` folder and the byte-identical foreign-file tests hold it
  to its own folders.
- **The bundle grows** from 3.3 MB to about 4.1 MB, in the kit and in every repository's
  `.omni-loop/bin/omni.mjs`.
- **A hand-edited copy is overwritten by update.** `omni check agents` turns red first, and the
  update PR names it.
- **The agents' conventions may move.** The folder and forms were read from each agent's docs on
  2026-10-14; a change is a one-table edit in `kit/lib/agents/` and `kit/lib/help/`.

The locked laws: the files this PRD changes state or enforce all twenty, through
`invariants.md`. It changes the meaning of one, and none of the others. Changing any needs
@pierrederval to approve the pull request on GitHub.

- **N-PRODUCT-13, amended:** the install could overwrite a person's own settings or files. Its new
  text lets the install own `.agents/skills/omni-*` only.
- **N-PRODUCT-4, which this change is judged by:** a change could switch its own gate off behind a
  green check. The amendment is approved by the law's owner on GitHub, never by the PR itself.
- Unchanged, and held by their tests: BR-PRODUCT-3, BR-PRODUCT-5, BR-PRODUCT-6, BR-PRODUCT-12,
  BR-PRODUCT-28, BR-PRODUCT-29, BR-PRODUCT-39, BR-PRODUCT-59, BR-PRODUCT-63, BR-PRODUCT-64,
  BR-PRODUCT-94, N-PRODUCT-3, N-PRODUCT-7, N-PRODUCT-8, N-PRODUCT-14, N-PRODUCT-15, N-PRODUCT-16,
  N-PRODUCT-17.

## Acceptance criteria

1. `omni init --agent codex --agent claude` in a fresh repository writes `agents: [codex, claude]`,
   every `.agents/skills/omni-<name>/` with its files, `.omni-loop/agents.json`, and the two
   `.claude/settings.json` keys, and its install PR commits exactly those paths and the usual
   `.omni-loop/` ones.
2. `omni init` with `agents` `[claude]` writes no `.agents/` path, as today.
3. Every `.agents/skills/omni-<name>/SKILL.md` has `name: omni-<name>`, the generated line, and the
   kit skill's body byte-identical; `pixel-perfect`'s sibling files are copied under the same paths.
4. A file in `.agents/skills/` the manifest does not name is never written or deleted, and an
   unowned `omni-*` folder stops init and update with one line naming it.
5. `omni update` rewrites, adds and removes owned folders by the manifest, removes them all when
   `agents` is `[claude]`, and its PR body lists one line per changed copy.
6. `omni check agents` is red on a hand-edited, missing or never-installed copy, naming
   `omni update`, and green otherwise; it runs in `omni check all`.
7. `omni help` shows `$omni-yolo <n>` for Codex, `/omni-yolo <n>` for Cursor, the Gemini form and
   `/omni:yolo <n>` for Claude, for the agents listed, under "Run these".
8. N-PRODUCT-13's entry carries the amended text, `Governs:` and `Enforced by:`, and the feature PR
   is approved by @pierrederval on GitHub.
9. `pnpm test`, `pnpm lint` and `pnpm typecheck` are green, and `kit/dist/` carries every skill.
