A service starts /omni:bug-fix, and every bug-fix PR shows a before/after GIF

PRD 1972. vertuo-cleaner opens an omni:bug issue for an error group, then waits for a person to paste /omni:bug-fix <issue url>. After this PRD it queues the job itself, with Pierre's kit token, and the pull request the job opens shows the bug before and after the fix.

Functional

1. The cleaner queues the fix

Today 
# the cleaner, with a kit token's access token
POST /api/runners/jobs
Authorization: Bearer eyJhbGciOi…
{"line": "/omni:bug-fix https://github.com/vertuoza/vertuo-backend-php/issues/123",
 "repo": "vertuoza/vertuo-backend-php", "target": {"kind": "any"}}

401 {"error": "Sign in first."}

# so the cleaner shows a person the line to paste
/omni:bug-fix https://github.com/vertuoza/vertuo-backend-php/issues/123

sendJob reads the browser's session alone. The runner's own routes (register, next, report) already take the Bearer.

After 
# 1. once an hour: the kit token for an access token
POST /api/ask/token
{"omni_token": "omk_…", "repo": "vertuoza/vertuo-backend-php"}
200 {"access_token": "eyJhbGciOi…", "expires_at": …, "workspace": …}

# 2. each bug
POST /api/runners/jobs
Authorization: Bearer eyJhbGciOi…
{"line": "/omni:bug-fix https://github.com/vertuoza/vertuo-backend-php/issues/123",
 "repo": "vertuoza/vertuo-backend-php", "target": {"kind": "any"}}
200 {"job": {…, "sentBy": "<Pierre>"}}

# refused
401 bad or expired Bearer, even beside a session
403 repository outside the workspace, or not a member

The same service, line check and rules as the browser's call. The token is Pierre's, made by Pierre with omni setup-token: every job is sent by Pierre.
