PRD 541 · /omni:visual-fix, a fast lane for small visual changes

The example throughout: “the sidebar background is too light”. Today it takes the whole loop. After, one command, one pick, one pull request.

From one line to a merged change

Today2 merges · about an hour
  1. /omni:brainstorm: design questions about a colour
  2. PRD issue, spec, before/after page
  3. /omni:plan: a plan of one slice
  4. Phase-0 PR: a person merges
  5. /clear, then /omni:yolo
  6. A wave: one sub-PR into a feature branch
  7. Outbox gate, ship, feature PR marked ready
  8. Feature PR: a person merges
  9. Retro and knowledge harvest run on it

Or it is done by hand, outside the loop: no issue, no label, nothing to track.

After1 merge · minutes
/omni:visual-fix 'the sidebar background is too light'
  1. Opens issue #612 Visual: the sidebar background is too light, labelled omni:visual
  2. Finds the sidebar and its tokens; says what it will touch
  3. Shows today and five variations; you pick one
  4. Applies it on fix/612-sidebar-background, runs the preflight
  5. Looks at the real screen once
  6. Writes delivery/visual/0612-sidebar-background/before-after.html
  7. omni visual 612 → ok, then one PR: a person merges

No spec, plan, phase-0 PR, wave or outbox: you took the one decision there was.

Step 3: the variations page

The boundary
ChangeVisual fix?
A colour, token, spacing, font, copyyes
Markup or layout of an existing screenyes
A prop that hides an element, a hover stateyes
Data, fetching, a route, an APIno → brainstorm
A new screen, a new flow, a stored shapeno → brainstorm

Crossing the line stops the skill: a comment on the issue names what crossed it and gives the /omni:brainstorm line. No PR opens.

What stays the same

  1. /omni:brainstorm and /omni:yolo are unchanged, and remain the way in for anything with behaviour.
  2. A person merges every PR. The skill never merges.
  3. Every merge still cuts a kit release. A visual fix gets no release note, retro or knowledge PR.
  4. Next, as their own PRDs: /omni:bug-fix, then Bugs and Visual views in the Omni menu, which list the omni:visual issues and folders this lane leaves behind.
