PRD #1089 · before / after

Repository flow: a repository tailors how the loop plans, tests, opens and merges

Today every repository gets the same loop. After, a repository declares rules the CLI enforces, areas with their own rules, and Markdown hooks any agent follows: extending a step by default, replacing the act only where allowed, never the guard.

1 · Planning a PRD that adds a column and the code that reads it

Today 
$ omni plan check 912
wave 1  s1  database/migrations/2026_10_add_due.sql
            src/Invoice/DueDate.php
            src/kernel/Bus/Dispatcher.php
wave 1  s2  resources/js/invoice/DueDate.tsx
ok  2 slices, 1 wave, no collision

The plan passes. A person finds the mixed migration and the kernel change in review, after the slices are built.

After 
$ omni plan check 912
✗ s1  crosses areas migrations + kernel + default
      (migrations: slice alone, max 1 file)
✗ s2  wave 1 beside kernel slice s1
      (kernel: wave first)
  → split s1: migration · kernel · invoice code
$ omni plan check 912   # after the split
ok  landing 1/2  s1 migration
    landing 2/2  wave 1 s2 kernel · wave 2 s3 s4

The repository's rules shape the plan before a line is written.

2 · Building and merging a kernel sub-PR

Today 
# /omni:do-work s2
pnpm test                 # commands.preflight, every slice
gh pr create …            # the kit's own
# /omni:wave
gh pr merge 1203 --squash --delete-branch

Same test command, same PR opening and same merge for every path in every repository.

After 
$ omni flow show do-work.test --prd 912 --slice s2
area     kernel
replace  .omni-loop/flow/kernel/tests.md
after    .omni-loop/flow/contract-tests.md
kit step replaced
$ omni flow verdict do-work.test --from out.txt
ok
$ omni flow check merge --pr 1203
not ok  kernel: approval person  # waits, wave moves on

The kernel's own test hook runs; a person approves before the wave merges it.

3 · The flow, as the repository writes it

Today 
# .omni-loop/config.yml
commands:
  preflight: pnpm test
landings:                 # #1086
  alone: ['^database/migrations/']
pr:
  openWith: /create-pr    # Claude-only

Two one-off keys, and prose forms nothing checks.

After 
# .omni-loop/config.yml
flow:
  hooks:
    pr.open: { replace: .omni-loop/flow/open-pr.md }
  areas:
    kernel:
      paths: ['^src/kernel/']
      rules:
        plan: [ { slice: { alone: true, maxFiles: 5 } },
                { wave: first } ]
        subPr: { approval: person }
      hooks:
        do-work.test: { replace: .omni-loop/flow/kernel/tests.md }
    migrations:
      paths: ['^database/migrations/']
      rules:
        plan: [ { slice: { alone: true, maxFiles: 1 } },
                { landing: alone } ]

Data and Markdown paths only: no repository code runs, and no Claude path is required.

What stays the same

With no flow key, the loop behaves exactly as today. Signing, labels, PR links, the default-branch guard, the territory check, omni plan check and the outbox gate are never replaced by a hook.
