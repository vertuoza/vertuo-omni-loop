Functional

Today

Where lines come from

  1. Only declared consumes, set by hand on Repositories & approvers. Vertuoza declares none: no line.
  2. Each PRD's targets are parsed on every plan push (plan_repository_names()), but only to link repositories to the product; nothing keeps them per PRD.
  3. Layout: a centre and two fixed rings in a 960 × 500 sky, whatever the count.
After

Targets stored once, lines from every multi-repository PRD

  1. On each plan push, the step that already resolves the plan's ## Repositories also writes prd_targets (one row per PRD and repository); the migration backfills it from every dossier's latest plan. Shipped PRDs never change again.
  2. The page reads those rows (no plan text) and draws one line per pair a PRD targeted, shipped or in flight; width by how many PRDs share it; bright with moving dots when one is in flight. Declared consumes stay as thin arrows.
  3. Layout: seeded forces (shared PRDs pull, stars and labels repel), then a separation pass until no label box overlaps; the sky grows taller with the count.
