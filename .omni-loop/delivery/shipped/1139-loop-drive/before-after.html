Loop drive

PRD 1139. /loop /omni:drive builds your own PRDs from inbox to ready, one step of a loop plan per tick. It stops on its own when every PRD waits on a person, and the Omni app's new Loop page shows it while it runs.

1. In the terminal

Today each PRD needs a person to type the next command. After, one command plans the work across PRDs and runs it step by step.

2. Two PRDs that touch the same files

Today nothing looks across PRDs, so they collide at merge time. After, the loop plan puts colliding steps in order, and the order is the plan's to change, with a reason.

PRD 1030 wave 2 and PRD 1017 wave 1 both edit apps/galaxy/src/nav/sidebar.ts on their own feature branches.

Collisions run one after the other, with the reason on the plan. blocked-by holds. Steps with no collision run beside each other.

The plan is frozen at the start. A stuck slice or an early ship makes v2, and every version is kept.

What stays the same

  • /omni:wave, /omni:yolo and /omni:yolo-fix run unchanged. /omni:pr-care only gains --once.
  • Every decision a slice takes still goes into its PRD's outbox, behind the same gate.
  • Nothing merges into main without a person. The loop never answers the outbox.
  • Brainstorm and phase-0 review stay a person's conversation.
