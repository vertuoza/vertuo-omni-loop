PRD 1679 · before / after

Context budgets

What every AI agent reads before it starts (the briefing, the playbook forms, CLAUDE.md) gets a byte ceiling in every repository that runs the loop. The kit measures it, the Omni App checks it on every pull request, and a ceiling only goes up when a person says yes.

Functional

1 · What an agent reads at each step

Today

Nothing measures it. These are the sizes omni kb show printed in this repository on 2026-10-12:

The releasing form is 1.9 KB on disk. Its pointer into the galaxy README runs past its section, so agents read about 33k tokens of screens and games before they write a spec. Nobody saw it.

omni budget measure context counts every target as it is read, and .omni-loop/budgets/context.json holds a ceiling for each.

Ceilings start at today's size, rounded up to the next KiB, so installing turns nothing red. ⚑ marks a target above the kit's guideline (16 KiB a form, 24 KiB a session): /omni:invade lists it as a TODO(human) to trim.

2 · A pull request makes a form bigger

Today

No check. The pull request merges, and every later session in the repository reads the extra 1.9 KB.

After · the omni / budgets check on the pull request
omni / budgets — 1 target over budget

Over budget: the design playbook form is 9.8 KB. Its ceiling is 8 KB.

Every AI agent working in this repository reads this file before it starts. When it grows, agents get slower, cost more and lose focus, so the team set a ceiling.

What grew: +1.9 KB in .omni-loop/knowledge/playbook/design.md, commit a1b2c3d.

Fix it for me: this pull request belongs to PRD 1702, so /omni:pr-care handles it by itself. Or paste this into Claude:

Trim .omni-loop/knowledge/playbook/design.md back under 8 KB without losing a rule; move detail into a linked file.

Or it needs the room: raise the ceiling in this pull request and file a high outbox item that says why. A person's answer turns this check green.

The same verdict comes from omni check context, which omni check all runs before an agent pushes. A pull request with no PRD is offered the trim only: raising goes through a PRD or /omni:bug-fix.

3 · The ceiling really needs to go up

Today, and in vnext

Here there is no ceiling to raise. In vnext, a budget is raised by writing an approval line in the commit message, which any agent can type.

After

The raise is a high outbox item (PRD 1548's OutboxStore): "raise form:design to 10 KiB, because…". No agent settles it. When a person answers, the server sends item-settled, and the check runs again:

omni / budgets — within budget

form:design 9.8 KB / 10 KiB · raised from 8 KiB, answered by a person on the outbox.

A later push that raises the same ceiling again no longer matches the answer, and needs a new one.
