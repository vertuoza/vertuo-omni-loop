## The question, in plain words

Without asking the Omni page, how does the graph tell a repository that belongs to no product from one whose product knowledge is simply not saved on this computer yet?

## The decision, in plain words

A repository with no Omni page address in its settings belongs to no product, so the last line says none. A repository with an address but no saved copy says offline.

## The intro, for fun

Is this repository an orphan, or did it just forget its phone at home?

## The punchline, for fun

We read the address book, never the phone line.

## The options, in plain words

A. A. No Omni page address set means none; an address set and no saved copy means offline.
B. B. Read none only from a saved reply that said the repository belongs to no product; everything else without a copy reads offline.
C. C. Read none when dossiers are off here (the switch the PRD page uses), offline otherwise.

## What I had to decide

Keep A, or pick B, which needs the saved copy (written by the product knowledge commands) to remember a reply of no product.

## What I did meanwhile

Every repository with an Omni page address reads offline until a copy is saved; one without reads none.

## What it costs to change later

A constant in one function of the neighbourhood module: either answer is a one-line change, no stored data moves.
